# Try Re in Act

This page gives a small **Bash RAS** you can run first.

There are three practical ways to try Re in Act:

1. **Direct Bash RAS setup** — install `reason` and `act`, then build the action space yourself.
2. **one-agent** — the full reference implementation with Python, TypeScript, and Bash RAS runtimes.
3. **Fast proxy experience** — launch a tool through `@one-agent/ria-proxy` and immediately experience Re in Act mode.

The relevant packages are:

- `@one-agent/reason`
- `@one-agent/act`
- `@one-agent/agent`
- `@one-agent/ria-proxy`

---

## 1. Direct Bash RAS Setup

If you want the interfaces directly in your shell, install the runtime surface:

```bash
# Required
npm install -g @one-agent/reason
# Optional
npm install -g @one-agent/act
```

Add this to your `CLAUDE.md` or `AGENTS.md`:

```md
# Bash with Reason in Act

Use `reason` to make local judgments on noisy output — keeps context window clean.

## Syntax

# With stdin observation
<cmd> | reason --prompt "goal: ..." [--prompt "constraints: ..."] - '{"key":"","score":0}'

# Inline observation
reason --prompt "goal: ..." "observation text" '{"key":""}'

# No observation (pure synthesis)
reason --prompt "goal: ..." --structure '{"key":""}'

## Rules

- **Structure is a JSON example**, not a Schema. Use real value types: `""` string, `0` int, `false` bool, `[""]` array.
- **`--structure` flag** is required when there is no observation argument.
- **Stack `--prompt` in order**: goal → context → constraints.
- **Pipe output with `jq`** to branch: `reason ... | jq -e '.deploy' && deploy.sh`
- **Chain calls** by piping one `reason` output as the next observation.

## Good for

Classification, extraction, prioritization, boolean gates, next-step selection.

## Keep in Bash

Loops, retries, branching logic, tool execution, side effects.
```

## 2. one-agent (Reference Implementation)

[one-agent](https://github.com/RIA-Spec/one-agent) is the full reference implementation of Re in Act, with Python, TypeScript, and Bash RAS runtimes bundled together.

```bash
npm install -g @one-agent/agent
one-agent auth    # configure the main agent model
one-agent reason auth   # configure the model used by reason() inside the RAS
one-agent repl    # start the interactive agent
```

Pick a runtime surface:

```bash
export RAS_MODE=python      # default — Python RAS
export RAS_MODE=typescript  # TypeScript RAS
export RAS_MODE=bash        # Bash RAS
```

Use `reason` and `act` directly inside a riff:

```python
log = open("build.log").read()
result = await reason(log + "\nDid the build succeed?", {"success": False, "reason": ""})
if result["data"]["success"]:
    await act("bash", {"command": "echo deploy"})
```

## 3. Fast Proxy Experience

If you want the quickest path to trying Re in Act mode, authenticate the proxy and then launch through it:

```bash
npx @one-agent/ria-proxy auth
npx @one-agent/ria-proxy launch opencode
```

This path is for immediate use: the proxy launches the target tool in Re in Act mode without requiring you to manually wire the action surface first.

## 5. Four Small Examples

Here are four smaller Bash examples. Each shows one advantage emphasized in the spec.

### 5.1 Fewer Round Trips

Make one local decision, then take the next step immediately inside the same action phase.

```bash
decision="$(act read_file '{"path":"build.log"}' | \
  reason \
    --prompt "Goal: decide the next local step for this failed build." \
    --prompt - \
    --prompt "Constraints and rules: return only action, reason, and retry_cmd." \
    --structure '{"action":"continue","reason":"","retry_cmd":""}')"

retry_cmd="$(printf '%s' "$decision" | jq -r '.data.retry_cmd')"
[ -n "$retry_cmd" ] && act bash "{\"cmd\":\"$retry_cmd\"}"
```

Without a RAS, this usually becomes another outer-loop turn. Here the local decision and the local follow-up stay together.

### 5.2 Clean Context Window

Keep the noisy log local and return only the bounded result that matters.

```bash
act read_file '{"path":"build.log"}' | \
  reason \
    --prompt "Goal: extract only the deployment-blocking issue from this log." \
    --prompt - \
    --prompt "Constraints and rules: ignore ANSI color, progress output, and repeated lines; return only issue and next_step." \
    --structure '{"issue":"","next_step":""}' | \
  jq .
```

The outer loop does not need the whole log. It only needs the denoised result.

### 5.3 Deterministic Control Flow

Let shell handle the loop deterministically, while `reason()` only makes the bounded judgment inside each step.

```bash
printf '%s\n' docs/docs/getting-started/intro.mdx docs/docs/getting-started/concepts.mdx | \
while read -r path; do
  act read_file "{\"path\":\"$path\"}" | \
    reason \
      --prompt "Goal: decide whether this page discusses subagents." \
      --prompt - \
      --prompt "Constraints and rules: return only path and mentioned true/false." \
      --structure '{"path":"","mentioned":false}'
done
```

The loop is not left to the model. The runtime controls the traversal; `reason()` only interprets each file.

### 5.4 Higher Effective Controller Variety

Use local discovery before action, instead of deciding everything upfront.

```bash
act --manual | \
  reason \
    --prompt "Goal: find the tools needed to collect the most relevant API and documentation context for this task." \
    --prompt - \
    --prompt "Constraints and rules: return only a JSON array of tool names. Prefer the smallest sufficient set." \
    --structure '["tool_name"]' | \
  jq -r '.data[]' | while read -r name; do
    act --manual "$name"
  done
```

This is the programmable part of the RAS: it can inspect, filter, branch, and adapt locally instead of using one fixed outer-loop response pattern.
